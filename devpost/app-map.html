Two Truths and an AI — App Map

Architecture reference, code route, and reusable practices for the deadpan lie detector.

App Overview

Two Truths and an AI is a single-card party game. The user enters three personal statements (two true, one false). A local backend proxy forwards the claims to Google Gemini with a deadpan persona prompt and strict JSON schema. The AI evaluates each statement with dry, observational wit, suspects one lie, and lets the user reveal the truth for a smug victory or begrudging crack in character.

The Core Data Flow

1. Browser Input User submits 3 statements in src/main.js via handleSubmission().
2. Local Proxy Vite dev server intercepts POST /api/analyze in vite.config.js, injecting GEMINI_API_KEY safely from .env.
3. Gemini API Calls gemini-3.5-flash (with gemini-3.8-flash fallback) enforcing response_schema for guaranteed JSON.
4. Reasoning Card Frontend renders 3 interactive statement cards with AI evaluations and a "My pick" badge.
5. Truth Reveal User clicks their real lie; app checks userLieIndex === suspectedLie and renders in-character victory or defeat punchline.

The 3-Stop Code Tour

Stop 1: State Store & Submission Trigger
src/main.js → handleSubmission()

Transitions the app to LOADING, calls the helper analyzeStatements(), and stores suspectedLie (1, 2, or 3) and reasoning (array of 3 strings) directly in the reactive state store before rendering Phase 2.

Stop 2: Safe Proxy & Schema Enforcement
vite.config.js → geminiProxyPlugin() & callGemini()

Ensures the client bundle never touches GEMINI_API_KEY. Configures response_schema so Gemini is contractually forced to reply with valid JSON matching { suspectedLie, reasoning }, with automatic 429/503 backoff and model cascade.

Stop 3: Interactive Outcome & Replay Loop
src/main.js → renderRevealCard() & resetState()

Compares player truth to AI guess. Selects a randomized victory line or begrudging defeat line from constant arrays, and resets all state cleanly back to Phase 1 on "Try me again".

A Practice to Reuse

Contract-Driven Structured Output with Backend Proxy: Instead of having client-side Javascript call LLMs directly and risking API key leaks in public repos, use a simple local dev middleware (like Vite's configureServer) to proxy the call. Couple this with the LLM provider's native response_schema rather than parsing free-form markdown or regex. This guarantees that your frontend logic always receives clean, type-safe data without runtime parsing failures.

How to Run Locally

Clone the repository, create a .env file with GEMINI_API_KEY=your_key, and run:

npm install
npm run dev

Open http://localhost:5173 in any modern browser.
